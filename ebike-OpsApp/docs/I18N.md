# Internationalization (i18n)

OpsApp shared strings live in Kotlin (not Android `strings.xml` / iOS Localizable.strings) so field-ops features and dual hosts share one catalog.

## Layout

| Piece | Path |
|-------|------|
| Keys | `shared/.../core/i18n/Str.kt` |
| ZH / EN text | `shared/.../core/i18n/StringCatalogs.kt` |
| Resolver + persist | `shared/.../core/i18n/OpsI18n.kt` |
| Process default | `Strings` + `LocaleContext.acceptLanguage` |

## Rules

1. **Add keys in pairs** — every new `Str` entry needs ZH and EN in `StringCatalogs`.
2. **User-facing feature messages** go through `Strings.t(Str.*)` (or `app.i18n.t` in Compose).
3. **Network** — `Accept-Language` is taken from `LocaleContext` (updated when language changes). Do not hardcode `zh-CN`.
4. **Persistence** — `SecureStore.KEY_LANGUAGE` (`ops_language`). If unset, default is **zh-CN** (does not follow the device locale). Host may still call `setLanguage` for an in-app switch.
5. **UI switch** — Android workbench Settings: 中文 / English via `app.i18n.setLanguage`.
6. **Placeholders** — templates use `{0}`, `{1}`, … (see `OpsI18n` format).
7. **Domain labels** — map filters / riding / task state use `Strings.t` getters so language switch updates without rebuilding models.
8. **Demo sample data** — repair types / warehouse component names / fault history also resolve via `Strings.t` (not hardcoded ZH).
9. **Legacy API sentinels** — warehouse pageList uses Chinese `"全部"` as the “all components” token.
   UI chips show localized [Str.FilterAll]; outbound filters go through [WarehouseComponentFilter]
   (`toApiFilter` / `toDisplayList`) so EN locale never sends `"All"` to the server.

## Host wiring

```kotlin
OpsApp.create(
    config = config,
    secureStore = secureStore,
    systemLanguage = Locale.getDefault().toLanguageTag(),
)
// Compose: collect app.i18n.languageFlow so labels recompose after switch
```
