# 迁移规划

从遗留 `APP/`（Android 原生 + iOS 原生 + Flutter 模块 + Vue2 H5）迁移到 `ebike-OpsApp`
（Kotlin Multiplatform 共享逻辑 + 双端原生 UI）。

## 决策前提

规划基于三条已确认的约束：

1. **可以砍范围** —— 管理、审核、报表类功能移交 `pc` 管理后台或移动自适应 H5，不在 App 内重复实现。
2. **iOS 必须与 Android 功能对等** —— 不接受 iOS 做功能子集。
3. **鸿蒙暂不实现，但架构要留余地** —— 不为鸿蒙牺牲当前选型，改为约束「将来只需重写 UI 层」。

由此确定的技术路线：**KMP 共享逻辑 + 双端原生 UI**。范围收敛后原生能力（BLE、地图聚合、后台定位）
在总工作量中占比上升，跨端 UI 框架能省下的比例相应下降，因此「接原生的摩擦最小」权重高于「少写一套 UI」。

选型对比过程与被否方案（Compose Multiplatform 全量、Flutter 收敛、uni-app 主壳）见 `ARCHITECTURE.md`
的「技术决策记录」。

## 范围结论

| 指标 | 数值 |
|------|------|
| 遗留 Android 业务屏幕（去除 9 个基类与脚手架） | 110 |

## 阶段划分

工期为**粗估**，假设投入：架构 / KMP 1 人、Android 2 人、iOS 2 人、后端配合 0.5 人、测试 0.5 人。
P3 与 P4 可部分并行。

### P0 范围冻结与开源边界（2–3 周）

| 项 | 内容 |
|----|------|
| 目标 | 冻结现场端功能边界，清理开源阻碍 |
| 交付 | 签字版功能清单；`pc` 侧缺口列表；开源合规检查表首轮通过 |
| 关键动作 | 逐模块与运维业务方确认移出项；确认 `pc` 需补的移动端自适应范围；向硬件组索取蓝牙协议文档 |
| 判据 | 功能清单无「待定」项；`OPEN-SOURCE.md` 中密钥与闭源 SDK 处置方案确定 |

**P0 不完成不进 P1。** 范围没冻结就写代码，等于把遗留工程的重复问题原样搬过来。

### P1 共享层骨架（4–6 周）

| 项 | 内容 |
|----|------|
| 目标 | `shared` 模块可被双端依赖，跑通一条真实业务闭环 |
| 范围 | Ktor 网络层 + 现有 `Authorization` 与时间戳签名；错误码；配置加载；日志；登录与切换服务区闭环 |
| 交付 | Android 登录走 `shared`；iOS 引入 XCFramework 调通同一接口；CI 产出双端产物 |
| 判据 | 同一份签名代码在双端通过 `/business/*` 联调；登录、Token 刷新、租户切换双端行为一致 |

同期完成并发模型统一：`shared` 内用协程与 Flow，iOS 侧引入 SKIE 之类桥接，替换遗留 RxJava / RxSwift。

### P2 平台能力契约（4–6 周，依赖蓝牙协议文档）

| 项 | 内容 |
|----|------|
| 目标 | BLE、定位、扫码、地图定义为 `expect` 契约，实现留各端 |
| 范围 | `BleTransport`、`LocationTracker`、`CodeScanner`、`MapProvider`、`SecureStore` |
| 交付 | 「蓝牙优先 → 网络兜底」车控策略下沉到 `commonMain`；仓库内提供 BLE 模拟实现 |
| 判据 | 双端车控走同一决策代码；关闭真实 SDK 时用模拟实现仍可跑通任务流程 |

### P3 现场作业主干（10–14 周）

按依赖顺序迁移，每块完成即双端同步上线灰度：

1. 首页地图与车点聚合、车辆列表与详情
2. 扫码与车控（开关锁、响铃、电池仓）
3. 任务执行：换电 → 挪车（含批量与扎堆）→ 巡检 → 维修
4. 仓库出入库
5. 生产现场作业（检测、中控绑定、上下架）
6. 报修上报与拍照
7. 后台定位与轨迹上报

判据：每块的 Android 与 iOS 行为一致，遗留对应入口下线，线上灰度无回退。

### P4 去 Flutter（4–6 周，与 P3 并行）

Flutter 约 20 个路由分三类处置：

- **移出**：挪车分析、智能调度、图表页、车辆审核 → 交 `pc`（或另立项）
- **迁入（现场 / 任务）**：任务列表 / 我的任务 / 任务详情 / 任务扫码 / 仓库记录 → 迁到本项目
- **迁入（数据分析 · CMP 重写）**：底栏「数据分析」四卡不再交 `pc` / `webH5`，在本项目用
  Kotlin + Compose Multiplatform 重写（`shared` 状态机 + `sharedUi` 列表/看板 + 宿主地图页）：
  1. **车况分布**（先做）：列表分档 + 点档进地图（复用聚合 / 围栏）
  2. **线下运维**（已落地）：四 Tab 统计/趋势/排名看板（Canvas 自绘，无第三方图表库）
  3. **站点监控**（已落地）：站点列表筛选项 + 详情 Canvas 图（App 口径，与 PC 站点监控不同）
  4. **还车分布**（已落地）：订单还车 DotScatter 散点地图（腾讯 `sdk-utilities`，勿用普通 Marker 硬铺）

判据：宿主不再启动 FlutterEngine；`Merchant-Flutter` 与 MethodChannel 桥接代码删除；
数据分析入口不再 `comingSoon`（未开工项可暂留占位，但车况分布必须可点进真实页）。

### P5 iOS 对等收口（4–6 周）

遗留 iOS 存在独立债务，需单独立项，不算在功能迁移里：

- 版本号 1.0.0 与 Android 3.7.4 不同步 → 统一版本策略
- APNs 集成为空壳（`RepairOrderAPNSManger.swift`）→ 补齐推送
- 地图仅支持腾讯 → 按 `MapProvider` 补齐海外分支
- 后台定位实现与 Android 语义不一致 → 对齐上报频率与权限引导

判据：功能矩阵零缺口；双端版本号统一；双端权限引导文案与时机一致。

### P6 表单动态化（4 周，可选后置）

任务、巡检、审核字段由后端 schema 下发，双端各实现一份渲染器。
这同时是鸿蒙余地的落地形式：新平台成本变成「一层渲染器」而不是「一个 App」。

判据：新增任务类型与租户字段差异不再需要发版。

## 里程碑

| 里程碑 | 对应阶段 | 含义 |
|--------|---------|------|
| M1 范围冻结 | P0 完成 | 功能边界与开源边界确定 |
| M2 双端共享登录 | P1 完成 | KMP 链路在双端跑通 |
| M3 车控统一 | P2 完成 | 车控策略单点实现 |
| M4 现场闭环可用 | P3 第 1–4 项完成 | 运维员可用新 App 完成日常主流程 |
| M5 Flutter 下线 | P4 完成 | 技术栈由 4 降到 2 |
| M6 双端对等 | P5 完成 | iOS 不再是功能子集 |
| M7 遗留下线 | M4–M6 全部灰度通过 | `APP/` 停止维护 |

累计工期粗估 **7–9 个月**（含并行）。

## 风险登记

| 风险 | 等级 | 影响 | 应对 |
|------|------|------|------|
| 私有蓝牙协议无文档 | **阻塞** | 车控无法在新架构落地，P2 与 P3 全部卡住 | P0 期间向硬件组索取协议或可复用封装；同时用模拟实现解耦开发进度 |
| 闭源 BLE SDK 无法开源分发 | 高 | 影响开源目标 | 接口化 + 模拟实现入库，真实 SDK 走私有 Maven / 私有 Pod |
| 地图车点聚合性能回退 | 高 | 首页体验劣于遗留版本 | 保留遗留聚合算法思路，先做千级车点压测基线再迁 |
| iOS 团队 KMP 上手成本 | 中 | P1 延期 | P1 安排 KMP 集成与调试专项；接口暴露风格向 Swift 友好靠拢 |
| `pc` 后台移动端体验不足 | 中 | 移出功能被业务方拒收 | P0 明确 `pc` 缺口清单并排期，先补再移 |
| 遗留密钥已在历史提交中 | 中 | 开源后泄露 | 新仓库独立起点，不迁移遗留 git 历史；泄露密钥一律轮换 |
| 后台定位在新系统版本受限 | 中 | 轨迹上报缺失 | P3 单独验证 Android 与 iOS 最新版本的保活与权限策略 |
| 范围回弹（业务方要求把移出功能加回 App） | 中 | 工期与 iOS 对等目标失守 | 变更走评审，加回一项须给出对应的删减项 |

## 不做的事

明确排除，避免范围蔓延：

- 不迁移遗留 git 历史，本项目从干净提交起步
- 不把大屏做进 App —— 两块大屏继续是独立部署的静态站点，App 仅用可配置 URL
  （`tenant.json` → `h5.operationUrl` / `h5.revenueUrl`）WebView 打开。
  但**源码已迁入本仓 `webH5/`** 并重写为 Vue 3 + TypeScript，见 [`MODULE-INVENTORY.md` 第四节](MODULE-INVENTORY.md#四h5-处置)
- 不复活遗留死代码：MQTT 桥接、百度定位、高德导航跳转
- 不在 P6 之前做 UI 跨端共享实验
- 不承诺鸿蒙实现，只保证架构不阻碍
